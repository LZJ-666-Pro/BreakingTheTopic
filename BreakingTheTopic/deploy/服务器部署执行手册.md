> 服务器：腾讯云轻量 4核4G / 40G SSD / 300G月流量 / 上海
> 公网 IP：`124.220.203.95`　镜像：宝塔Linux面板 13.0.0　到期：2027-10-19
> 部署目标：10 个后端服务 + MySQL + Redis + Nacos（monitor 为空壳不部署；search 依赖 ES 暂不部署）

## 阶段一：服务器初始化（约 30 分钟）

### 1.1 拿到 SSH/宝塔入口
1. 腾讯云轻量控制台 → 实例 →「登录」（OrcaTerm 网页终端）或本地 `ssh root@124.220.203.95`
2. 控制台「应用管理」页获取宝塔面板地址、账号、密码，浏览器登录宝塔
3. **立即做宝塔安全三件套**：面板设置 → 改面板端口（如 38888）、改安全入口路径、绑定宝塔官网账号

### 1.2 防火墙放行（腾讯云控制台「防火墙」页 + 宝塔「安全」页 两边都要放）
| 端口 | 用途 |
|---|---|
| 22 | SSH |
| 80 / 443 | 管理端前端站点（Phase B 上 HTTPS） |
| 8080 | 网关 |
| 8100 / 8200 / 8300 / 8400 / 8500 / 8600 / 8700 / 8900 | 小程序直连的业务服务 |
| 宝塔面板端口 | 自己记住，勿外传 |

**禁止放行**：8848(Nacos)、3306(MySQL)、6379(Redis)——全部只走服务器本机。

### 1.3 装 JDK 17
```bash
# 腾讯云宝塔镜像底层为 TencentOS/OpenCloudOS（yum 系）
dnf install -y java-17-openjdk java-17-openjdk-devel
java -version   # 确认 17.x
```
（若为 Ubuntu 底层则 `apt install -y openjdk-17-jdk`）

### 1.4 宝塔装中间件
- 软件商店 → 安装 **MySQL 8.0**；装完在数据库页把 root 密码改为 secrets.env 里的 `DB_PASSWORD` 值
- 软件商店 → 安装 **Redis**；保持默认（仅监听 127.0.0.1，无密码即可，防火墙未放行 6379）

## 阶段二：Nacos 独立部署 + 配置迁移（约 20 分钟）

> 关键：所有服务的配置（数据源等）都在本地 Nacos 的内嵌 derby 里，必须迁到服务器 Nacos，否则服务起不来。

### 2.1 安装
```bash
cd /opt
# 版本号以本地容器内一致为准（可用 2.2.x）
wget https://github.com/alibaba/nacos/releases/download/2.2.3/nacos-server-2.2.3.tar.gz
tar -xzf nacos-server-2.2.3.tar.gz
sed -i 's/-Xms2g -Xmx2g/-Xms256m -Xmx256m/' /opt/nacos/bin/startup.sh
```

### 2.2 注册为 systemd
```bash
cat > /etc/systemd/system/nacos.service <<'EOF'
[Unit]
Description=Nacos Server
After=network.target
[Service]
Type=forking
ExecStart=/opt/nacos/bin/startup.sh -m standalone
ExecStop=/opt/nacos/bin/shutdown.sh
Restart=on-failure
[Install]
WantedBy=multi-user.target
EOF
systemctl daemon-reload && systemctl enable --now nacos
```

### 2.3 迁移配置（SSH 隧道访问，不开公网 8848）
```powershell
# 本地 Windows PowerShell 开隧道
ssh -N -L 8848:127.0.0.1:8848 root@124.220.203.95
```
1. 本地浏览器开 `http://127.0.0.1:8848/nacos`（账号 nacos/nacos）→ 确认这是**本地容器**的 Nacos → 配置管理 → 配置列表 → 全选 → **导出** zip
2. 新开标签页 `http://127.0.0.1:8848/nacos`——⚠️ 此时同一地址已是**服务器** Nacos（隧道指向服务器）→ 登录 → 配置管理 → **导入**该 zip
3. 导入后核对：每个 poti-* 服务都有对应配置且 Data ID 前缀正确
4. 用完关掉隧道进程

## 阶段三：本地打包 + 上传（约 20 分钟）

## 阶段四：服务器落库 + 环境变量 + 注册服务（约 30 分钟）

### 4.1 导入数据库
```bash
mysql -uroot -p < /opt/poti/poti_dbs.sql
mysql -uroot -p -e "SHOW DATABASES LIKE 'poti%';"   # 应见 9 个库
```

### 4.2 创建环境变量文件（密钥只进服务器，不进 git）
```bash
mkdir -p /opt/poti && nano /opt/poti/poti.env
```
按 `deploy/server/poti.env.template` 逐项填写，值取自本地 `deploy/secrets.env`：
`chmod 600 /opt/poti/poti.env`
> 注意两项：① `SPRING_DATASOURCE_PASSWORD` 与 `DB_PASSWORD` 填同一个值；② 若部署后**小程序登录失败**，优先核对 `WX_SECRET` 是否为微信公众平台当前有效值（auth 服务历史默认值与 secrets.env 曾不一致）

### 4.3 安装 systemd 服务（10 个）
```bash
# 上传 deploy/server/poti-services-install.sh 后执行
bash /opt/poti/poti-services-install.sh
```
脚本行为：生成 10 个 `poti-<服务>.service`（自动注入 poti.env、统一 JVM `-Xms128m -Xmx384m`）→ 启动 → 轮询健康检查。

### 4.4 启动自检
```bash
for p in 8080 8100 8088 8200 8300 8400 8500 8600 8700 8900; do
  echo -n "$p: "; curl -s -o /dev/null -w '%{http_code}\n' http://127.0.0.1:$p/actuator/health
done
# 全部 200/UP 即成功；个别 000/503 等 30 秒重查（服务有启动时差）
```
排障：`journalctl -u poti-user -n 100 --no-pager`（换成对应服务名）。
> 常见失败：报 `Could not resolve placeholder` = 阶段 2.3 配置没导入全；连不上库 = poti.env 密码与 MySQL root 不一致。

## 阶段五：前端部署（约 20 分钟）

### 5.1 管理端（Vue 静态站点）
```powershell
# 本地构建
cd d:\download\project\BreakingTheTopic\BreakingTheTopic\poti-admin
npm run build    # 产出 dist/
```
宝塔 → 网站 → 添加站点 `admin`（纯静态，根目录 `/www/wwwroot/admin`）→ 上传 `dist/` 全部内容到根目录 → 站点设置加反向代理：

验证：浏览器开 `http://124.220.203.95` 能看到管理端登录页并能登录。

## 附：日常运维速查

```bash
systemctl status poti-user        # 看某服务
systemctl restart poti-gateway    # 重启
journalctl -u poti-agent -f       # 跟日志
free -h && df -h                  # 内存/磁盘
# 宝塔不用时停掉省 250MB：systemctl stop bt && systemctl stop btpanel
```

- Agent 会话定时清理任务已内置在 poti-agent（每日凌晨 3 点，90 天保留期），无需额外配置
- 服务器重启后 systemd 会自动拉起全部服务（nacos 先行、服务 Restart=on-failure）
