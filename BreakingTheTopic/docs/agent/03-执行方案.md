## 1. 分期总览

| 阶段 | 内容 | 交付判据 |
|---|---|---|
| M1 地基 | agent 服务骨架 + 数据模型 + LLM 网关 | 服务注册 Nacos、对话链路能通（无工具） |
| M2 工具调度 | 工具注册中心 + P0 六个工具 + Function Calling 循环 | 四个示例场景（PRD 第 3 节）全部走真实数据跑通 |
| M3 前端体验 | 小程序助手页 + 流式渲染 + 动作卡片 + 引用标注 | PRD FR-1/4/5 全部可操作 |
| M4 安全与收尾 | 配额、限流、注入防护、内容合规、日志看板、降级通道 | PRD 共享规则 R-1~R-6 与 FR-6 全部生效 |

依赖关系：M1 → M2 → M3 → M4 串行为主；M3 的页面骨架可与 M2 并行（先接 mock 数据）。

## 2. 任务分解

### M1 地基（预计 2~3 天）

| # | 任务 | 产出 |
|---|---|---|
| 1.1 | 新建 `poti_agent` 库与三张表（02 规范第 5 节） | init SQL 固化到 `poti/mysql/init/36_agent_*.sql` |
| 1.2 | 搭建 poti-agent 服务（8900）：Nacos 注册、JWT 过滤器接入、Feign/MyBatis-Plus 骨架 | 服务可启动、被网关路由 |
| 1.3 | 引入 LangChain4j 1.0.0-beta3 依赖（langchain4j + langchain4j-open-ai），模型走智谱 OpenAI 兼容端点（`https://open.bigmodel.cn/api/paas/v4`，密钥沿用 AI_API_KEY），验证 AiServices 对话可用（父 pom Boot 2.7 无法上 Spring AI 1.0，详见 02 规范 3.0；流式 MVP 由前端打字机模拟） | OpenAiChatModel 直连智谱可对话 |
| 1.4 | `/agent/chat/sync` 最小链路：纯对话（无工具）+ 会话/消息落库 | curl 可多轮对话 |

**验收**：不接业务数据，直接对话能正确回答"你能做什么"并列出能力清单；`agent_message` 有记录。

### M2 工具调度（预计 3~4 天）

| # | 任务 | 产出 |
|---|---|---|
| 2.1 | LangChainConfig：OpenAiChatModel Bean + AiServices 装配 Assistant（@SystemMessage + @MemoryId），MessageWindowChatMemory 挂自定义 JDBC Store | AiServices 可带记忆调用、agent_chat_memory 落库 |
| 2.2 | AgentToolService：6 个 P0 工具的 @Tool 方法（复用/新增各服务 internal 接口），AOP 切面写 agent_tool_log | 每个工具可独立验证 |
| 2.3 | 编排联调：工具循环由框架托管，Advisor 实现 MAX_ROUNDS=5 上限，ChatMemory 自定义 JDBC 实现 | 四个示例场景（PRD 第 3 节）全部走真实数据跑通 |
| 2.4 | 动作卡片：AgentAnswer 结构化输出（.entity 映射）+ 解析失败降级为纯文本 | 回答输出符合 02 规范 3.3 |

**验收**（对照 PRD 第 3 节示例逐条跑）：

- "我最近哪块薄弱？" → 返回真实正确率最低分类，`tool_trace` 含统计+错题分布两次调用；
- "帮我找几道 SpringCloud 的难题" → 返回 ES 搜索真实题目；
- "我这周刷了多少题" → 数字与统计页一致；
- 任一业务服务停掉后提问 → 相关部分降级说明，不 500。

## 3. 风险与应对

| 风险 | 影响 | 应对 |
|---|---|---|
| 智谱 API 限流/超时（出题任务与助手共用账号） | 助手响应慢或失败 | 独立限流池（02 规范第 9 节）；sync 降级；高峰期降低上下文窗口 |
| 小程序真机流式分块不稳定 | M3 体验受损 | sync 全量通道为默认保底，流式失败自动切换 |
| LLM 编造数据 | 信任崩塌（核心风险） | 工具结果截断+来源标注+数字必须来自 tool_trace，评审时人工核对抽查 |
| 单人开发周期拉长 | 上线延期 | M1/M2 为最小可用核，先内部可用再打磨 M3 |
| 成本失控 | 运营费用 | 每日配额 + token 计量看板 + 上下文截断三道闸 |

## 4. 上线与回滚

- 灰度：入口先对内部账号可见（配置开关），观察一周指标（提问量/成功率/成本）后全量；
- 回滚：关闭入口开关即完成用户侧回滚，agent 服务与数据保留；LLM 故障时切 sync + 降级话术，无需回滚版本；
- 数据安全：poti_agent 库独立，回滚不影响任何业务库。
