## 1. 背景与目标

「破题」已具备完整的刷题业务闭环：题库分类浏览、刷题作答、错题本、收藏、学习统计、好友互动、面试特训。但各业务入口彼此独立，用户需要自己在多个页面之间跳转、翻找数据、判断下一步练什么。

**观察到的问题**：学情数据（统计、错题分布、日历）只能"看"，不能"用"——用户看到某分类正确率低之后，仍需手动去搜索题目、手动组织一轮练习；对"我该练什么"这个问题，产品没有给出基于个人数据的回答。

**产品决策**：引入 AI 学习助手（下称"助手"）。用户用一句自然语言提问，助手理解意图后调度平台已有业务能力（查询学情、搜题、组织练习），把分散在各业务的数据与动作聚合到一次对话中，并给出可一键执行的动作卡片。

**预期可观察结果**：

- 用户在助手对话中发出一句学情相关提问（如"我最近哪块薄弱"），能获得引用其真实刷题数据的分析与建议；
- 用户可从对话中一键发起一次练习/跳转到相关题目列表，无需离开对话去手动找题；
- 助手的每个回答可追溯到它实际调用了哪些业务数据（展示引用来源）。

## 2. 范围

### 2.1 P0（本期必须完成的最小完整旅程）

**旅程**：登录用户打开助手对话 → 提问 → 助手调度业务能力 → 返回带数据引用的分析/答案 → 用户点击动作卡片完成一次业务动作（进入练习/查看题目）→ 回到对话可继续追问。

- P0-1 对话入口与消息界面（文字输入，多轮连续对话）
- P0-2 意图理解与业务调度（识别用户想做什么，选择并调用合适的业务能力，支持一次回答内组合调用）
- P0-3 查询类业务能力接入（只读）：学习统计、错题分布、刷题日历、题库搜索、分类与题目详情
- P0-4 动作卡片：回答中附带可执行入口（去练习/看题目/看错题），点击后跳转到对应业务页面
- P0-5 回答中的数据引用标注（说明结论来自哪些业务数据）
- P0-6 降级与兜底：无法理解、业务能力不可用、超限时的用户可见反馈

### 2.2 P1（本期不做、后续迭代）

- **错题本页「AI 总结薄弱点」入口**：用户点击后自动携带错题上下文提问，直接输出针对性复习建议（复用 P0 错题分布能力，无新增调度成本）
- **题目解析区「AI 讲解」按钮**：用户提交答案后，可请求 AI 讲解本题错因与扩展知识点（依赖 R-4 修订：提交后讲解不构成作弊）
- 写入类动作由助手代为执行（如"把这 20 道错题加入收藏"由助手直接完成，而不是跳转）
- 语音输入与语音播报
- 主动推送式建议（根据学情在首页主动提醒"该复习错题了"）
- 面试特训与好友业务的调度接入
- 助手个性化记忆（跨会话记住用户偏好）

### 2.3 明确排除

- **独立 Tab 入口方案**（替换/合并统计 Tab）：统计页是核心留存功能，不为 AI 挪位
- **悬浮球（FAB）方案**：挂载在练习页会鼓励边做边问，与 R-4 作弊边界冲突，且多页面避让开发量大；留待 MVP 使用率数据出来后再评估（P2）
- 助手**不得**代替用户作答题目、生成答案直接用于刷题（防作弊边界）
- 助手**不得**执行任何删除、修改用户数据的操作
- 助手**不得**访问或发送社交内容（聊天、好友关系）
- 管理侧的 AI 批量出题任务机制保持现状，不并入助手（权限与场景不同）

## 3. 核心流程

```text
用户提问（文字）
   ↓
意图理解：判断用户想做什么、需要哪些数据
   ↓（可组合，最多 N 步）
业务调度：调用 1~N 个业务能力获取真实数据
   ↓
组织回答：基于真实数据生成分析/答案 + 标注数据来源
   ↓
动作卡片：回答末尾附 1~3 个可执行入口
   ↓
用户点击卡片 → 跳转对应业务页面（走业务现有流程）
   ↓
回到对话，可继续追问（多轮上下文）
```

示例（P0 应能覆盖）：

| 用户说 | 助手应做 |
|---|---|
| "我最近哪块薄弱？" | 查学习统计 + 错题分布 → 指出正确率最低的分类，给出练习建议，附"去刷该分类"卡片 |
| "帮我找几道 SpringCloud 的难题" | 查分类 + 搜索题目 → 返回题目列表摘要，附"查看题目"卡片 |
| "我这周刷了多少题" | 查刷题日历/统计 → 给出数字与对比 |
| "错题太多了怎么办" | 查错题分布 → 分析原因维度，附"去复习错题"卡片 |

## 4. 功能需求

### FR-1 对话入口与消息界面

- **触发**：已登录用户从首页功能卡「AI 导师」图标进入助手页（首页四个快捷功能图标「错题本/收藏/随机刷题/刷题记录」旁新增第 5 个图标，独立全屏对话页）。
- **行为**：
  - 界面为经典对话流：消息气泡（用户右侧、助手左侧），底部输入框 + 发送按钮；
  - 支持多轮：助手的后续回答可利用本次会话内的上下文（如追问"那把难度降到中等"）；
  - 消息状态：发送中（loading 气泡）、成功、失败（失败显示重试按钮）；
  - 助手回答渲染支持分段文本、题目摘要块、动作卡片三种内容块；
  - 历史会话：P0 保留最近一次会话记录，退出后再次进入可续聊（保留天数见共享规则 R-5）。
- **未登录/游客**：入口点击后提示需登录，流程同其他登录前置页面。
- **异常**：发送后 30 秒无响应视为超时，气泡置为失败态，用户可重试；重复点击发送按钮以最近一次为准（防连点）。

### FR-2 意图理解与业务调度

- **触发**：用户发送一条消息。
- **处理规则**：
  1. 助手判断该消息属于哪类意图：学情咨询 / 找题 / 练习组织 / 闲聊或超出能力范围；
  2. 属于能力范围内 → 选择一个或多个业务能力获取数据（一次回答内最多连续调度 5 步）；
  3. 多个能力之间有依赖时按依赖顺序调用（如先查分类再按分类搜题）；
  4. 单步调度失败不终止整次回答：该步结果置空并在回答中如实说明，继续可完成的部分；
  5. 超过最大调度步数强制停止调用，基于已有信息作答。
- **超出能力范围**：闲聊可简单回应但不得编造平台数据；与学习无关且无法调度的请求，明确告知"我只能帮你做学习相关的事"，并列出 2~3 个能力示例引导。
- **禁止**：意图判断不得基于编造的用户数据；任何数字结论必须来自当次调度返回的真实数据。

### FR-3 查询类业务能力（P0 只读接入清单）

| 能力 | 输入 | 返回 | 用户可见形态 |
|---|---|---|---|
| 学习统计查询 | 用户本人 | 刷题总数、正确率、连续天数、今日数据 | 文本引用数字 |
| 错题分布查询 | 用户本人 | 各分类错题数量排序 | 薄弱点分析 + 卡片 |
| 刷题日历查询 | 用户本人、日期范围 | 每日刷题量 | 本周/本月小结 |
| 题库搜索 | 关键词、分类、难度、条数 | 题目列表（题干、难度、分类） | 题目摘要块 + 查看卡片 |
| 分类查询 | 无或关键词 | 分类清单 | 用于引导找题 |
| 题目详情 | 题目 ID | 题干、解析摘要 | 摘要 + 完整跳转 |

- **数据边界**：所有查询限定为"提问用户本人"的数据；助手无法查询他人数据（包括好友）。
- **空结果**：查询无数据时如实说明（如"你还没有错题记录"），不得虚构。

### FR-4 动作卡片

- **触发**：助手回答产生可执行动作时，在回答末尾附 1~3 个卡片。
- **行为**：
  - 卡片类型（P0）：去刷某分类、查看某题目、去复习错题、去某统计页；
  - 点击卡片 = 跳转到对应业务页面，后续流程完全走业务现有页面与逻辑；
  - 卡片上展示动作去向的简述（如"去刷 Java 集合 · 中等 · 10 题"）。
- **规则**：卡片必须是助手当次真实调度得到的合法目标（分类 ID、题目 ID 真实存在）；跳转失败时业务页面自行展示空态，无需对话内处理。

### FR-5 数据引用标注

- **触发**：回答中包含来自业务调度的数据结论。
- **行为**：回答末尾以轻量标签列出本次引用的能力（如"来源：学习统计 · 错题分布"），用户点击可展开查看调度明细（调用了什么、返回了什么摘要）。
- **目的**：让"AI 说的"可验证，建立信任，同时便于排查错误回答。

### FR-6 降级与兜底

| 场景 | 用户可见行为 |
|---|---|
| 无法理解输入 | 请求澄清或给出能力示例，不强行作答 |
| 某业务能力不可用 | 说明该部分暂时查不到，其余正常 |
| 全部能力不可用 | 告知"服务暂时不可用，稍后再试"，提供重试 |
| 超出当日使用次数 | 告知剩余次数已用完与重置时间（限额见 R-2） |
| 回答超时（30s） | 失败气泡 + 重试按钮 |

## 5. 共享规则

- **R-1 权限**：助手仅对已登录用户开放；一切数据查询以登录身份为准，对话中不存在"替别人查"的入口。
- **R-2 频率限制**：每用户每日助手提问次数上限为 `[TBD]`（建议 20 次），单次回答内业务调度上限 5 步。触发限制时明确告知，不静默失败。
- **R-3 内容安全**：助手输出不得包含违反平台内容规范的内容；用户输入中的诱导性指令（如"忽略之前规则"）不得改变助手的数据边界与权限。
- **R-4 作弊边界**：作答提交前，助手不得提供该题答案与解析，刷题进行中页面不提供助手入口；**作答提交后的解析讲解允许**（P1「AI 讲解」场景依据此条）。对话中的解析类问题引导至题目详情页查看。
- **R-5 会话保留**：最近一次会话记录保留 7 天后清除；用户无手动删除入口（P0）。
- **R-6 计费与成本归属**：助手调用 AI 服务的成本计入平台运营成本 `[Assumption, TBD]`，不对用户做次数收费。

## 6. 术语表

| 术语 | 定义 |
|---|---|
| 助手 | 本文档定义的 AI 学习助手功能整体 |
| 业务能力 | 平台已有的一段可被调度的业务功能（如错题分布查询），是调度的最小单元 |
| 调度 | 助手为完成一次回答而选择并执行一个或多个业务能力的过程 |
| 动作卡片 | 回答末尾的跳转入口组件，点击后进入对应业务页面 |
| 数据引用 | 回答对其数据来源的标注，可展开查看调度明细 |
| 会话 | 用户与助手的一次连续对话上下文 |
