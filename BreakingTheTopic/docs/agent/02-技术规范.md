## 1. 总体架构

```text
小程序（agent 页面）
   │  HTTPS（JWT + X-User-Id）
   ▼
poti-agent 服务（新，8900 端口）
   ├─ 会话管理（agent_session / agent_message）
   ├─ 编排引擎（Spring AI：ChatClient + Tool Calling 循环）
   ├─ 工具注册中心（业务能力 → @Tool 工具方法）
   ├─ LLM 网关（智谱 GLM，Spring AI 模型层封装，计量与限流）
   └─ 工具执行器（@Tool 方法内 Feign 调用各业务服务 internal 接口）
         ├─ poti-user      学习统计 / 日历 / 签到
         ├─ poti-question  分类 / 搜索 / 题目详情
         ├─ poti-wrongbook 错题分布
         ├─ poti-favorite  收藏查询
         └─（后续）poti-practice / interview
```

**设计原则**：

1. **Agent 是编排者不是数据源**：所有业务数字来自各服务真实接口，agent 服务不缓存业务事实数据，回答可引用、可复算。
2. **工具只读优先**：P0 注册的工具全部为查询类，写入动作通过动作卡片跳转由用户在业务页面完成，规避越权与误操作。
3. **能力复用**：LLM 继续使用智谱开放平台（与现有批量出题同一账号体系，密钥走环境变量注入）；业务接口直接复用现有 internal 接口，不足处新增，不另建旁路查询。

## 2. 新服务 poti-agent

| 项 | 规范 |
|---|---|
| 端口 | 8900 |
| 注册中心 | Nacos（复用现有命名空间与配置方式） |

## 3. 编排引擎设计（Spring AI）

### 3.0 框架选型说明

客户明确要求采用 LangChain / Spring AI 技术路线。**落地结论：LangChain4j 1.0.0-beta3**——项目全家桶为 Spring Boot 2.7（Java 17），Spring AI 1.0 要求 Boot 3.2+，升级需 javax→jakarta 全量迁移不可行；LangChain4j 为纯 Java 库无 Spring 版本绑定，且与现有 poti-common 安全体系直接复用。模型接入用智谱 **OpenAI 兼容端点**（`https://open.bigmodel.cn/api/paas/v4`）+ `langchain4j-open-ai` 模块，与文档原备选方案一致。AiServices 声明式接口托管工具循环，安全规范不变。

### 3.1 调度循环（Spring AI Tool Calling）

```text
ChatClient 组装：system prompt + 工具清单（@Tool 自动生成 JSON Schema）+ 会话记忆
   ↓
chatClient.prompt().tools(...).stream() 发起调用
   ↓
模型返回 tool_calls → Spring AI 框架内部自动执行注册的 @Tool 方法并回填结果
   ↓
框架自动继续对话直至模型产出最终回答（多轮工具循环由框架托管）
   ↓
最终回答结构化解析（文本 + sources + actions）
```

- 模型接入：`spring-ai-starter-model-zhipuai`（官方智谱 starter）；若 starter 版本滞后，改用 `spring-ai-starter-model-openai` 指向智谱的 OpenAI 兼容端点（base-url 覆盖），二选一在 M1 验证后固化；
- **不再自研 while 循环**：tool_calls 的「调用→执行→回填→继续」由 Spring AI 托管，自研部分收缩为：每轮次的拦截观测（`ChatClientRequestInterceptor`/Advisor 记日志计量）、步数上限控制；
- `MAX_ROUNDS = 5` 通过 Advisor 实现：请求前检查本轮已执行工具次数，超限则剥离 tools 选项强制模型直答；
- 单工具返回注入 prompt 上限 2000 字符的截断逻辑内置在 @Tool 方法返回前（见 4.3），不依赖框架；
- 温度 0.3~0.5，经 `ZhiPuAiChatOptions` 配置。

### 3.2 上下文与多轮（ChatMemory）

- 使用 Spring AI `ChatMemory` 抽象，实现自定义 `JdbcChatMemoryRepository` 落 `agent_message` 表（会话与业务表合一，避免框架内存存储重启即失）；
- 记忆窗口：最近 10 轮消息 + 工具调用结果摘要；
- **用户上下文摘要**（今日刷题数/连续天数/错题总数，TTL 10 分钟）仍由工具执行器顺带刷新，作为 system message 追加注入，减少工具轮次。

### 3.3 结构化输出（动作卡片）

最终回答用 Spring AI 的结构化映射：定义 `AgentAnswer` record（text / sources / actions），以 `.entity(AgentAnswer.class)` 输出；解析失败时降级为纯文本回答（无卡片），不报错给用户。

## 4. 工具注册规范

### 4.1 工具描述

每个业务能力实现为一个 Spring AI 工具方法：`@Tool(name, description)` 注解 + `@ToolParam` 参数注解，JSON Schema 由框架从方法签名自动生成，无需手写。工具方法集中在一个 `AgentToolService` 类中按业务分组，新增工具 = 新增一个 @Tool 方法 + 一个 Feign 调用。权限标签（只读/写、数据边界）以自定义注解元数据标注，供 code review 与后续权限网关使用。

### 4.2 P0 工具清单

| 工具名 | 业务来源（目标接口） | 读/写 | 说明 |
|---|---|---|---|
| `get_study_statistics` | user 服务统计接口 | 读 | 总量/正确率/连续天数/今日 |
| `get_wrongbook_distribution` | wrongbook internal 分布接口 | 读 | 按分类错题计数排序 |
| `get_practice_calendar` | user 服务日历接口 | 读 | 指定年月每日刷题量 |
| `search_questions` | question 搜索接口（ES） | 读 | 关键词+分类+难度+数量 |
| `get_category_list` | question 分类接口 | 读 | 分类树/清单 |
| `get_question_detail` | question 详情接口 | 读 | 题干+解析摘要（不含直接答案字段时做裁剪） |

**裁剪规则**：`get_question_detail` 返回给 LLM 的内容剥离答案/正确选项字段，仅保留题干与解析要点，从协议层落实 PRD R-4 作弊边界。

### 4.3 工具执行器规范

- 一律走 Feign 调用各服务 `/xxx/internal/**` 接口，携带 `X-Internal-Token`（延续内部令牌收权机制）；
- **参数白名单**：userId 一律由服务端注入（当前登录用户），工具方法不暴露 userId 形参，Spring AI 生成的 Schema 中不含该字段，从源头杜绝模型伪造；
- **安全逻辑在工具方法内部实现**（框架不感知）：返回前截断（2000 字符）、脱敏（剥离答案字段）、结构化信封 `{"ok": true, "data": ...}` / `{"ok": false, "error": ...}`；
- 单工具超时 5s（Feign 层配置），失败返回结构化错误 `{"error": "TOOL_TIMEOUT"}` 回填模型，由其组织降级话术；
- 每次工具执行写 `agent_tool_log`（工具名、参数、耗时、轮次），在 @Tool 方法内统一经 AOP 切面记录。

### 4.4 工具新增审批约定（防扩张）

新增工具必须满足：只读或经二次确认的写操作、不涉及他人数据、不涉及删除。注册表内以 `读写标签 + 数据边界标签` 标注，code review 时按此审查。

## 5. 数据模型（poti_agent 库）

```sql
agent_session     会话表：id, user_id, title, last_active_time, context_digest(上下文摘要JSON), deleted, create_time
agent_message     消息表：id, session_id, role(user/assistant), content(JSON: text/sources/actions),
                  tool_trace(JSON: 调用明细), status(0成功/1失败/2超时), create_time
agent_tool_log    调度日志：id, message_id, tool_name, params(JSON), result_digest, cost_ms, round, create_time
agent_quota       配额表：id, user_id, quota_date, used_count（每日提问计数）
```

- 消息内容存 JSON，渲染结构（文本分段/卡片）与业务数据解耦；
- `tool_trace` 支撑 PRD FR-5 引用标注展开；
- 7 天保留策略由定时任务清理 `agent_message`（session 保留最近一次）。

## 6. 接口定义（对外）

| 接口 | 方法 | 说明 |
|---|---|---|
| `/agent/chat/stream` | POST | 发送提问，SSE 流式返回（`enableChunked` 分块事件：`delta` 增量文本 / `tool` 调用事件 / `done` 最终结构 / `error`） |
| `/agent/chat/sync` | POST | 非流式降级通道（流式不可用时前端自动切换） |
| `/agent/session/current` | GET | 拉取最近会话消息 |
| `/agent/session/messages` | GET | 展开某条消息的 tool_trace |

- 请求体：`{ "sessionId"?: long, "message": string }`；身份取 `X-User-Id`；
- 流式实现：`SseEmitter` + 后台线程驱动调度循环；智谱侧使用流式 API，逐段转发；
- 小程序端：`wx.request({ enableChunked: true })` 接收分块；开发者工具与真机均需验证（真机分块行为 `[TBD]`，所以保留 sync 降级通道）。

## 7. 安全规范（延续现有安全体系）

1. **鉴权**：全接口 JWT 必需；`/agent/**` 不进入白名单；内部接口仅 `X-Internal-Token` 且仅 `/internal/**` 路径（与 JwtAuthenticationFilter 现行收权一致）。
2. **越权防护**：会话归属校验（sessionId 必须属于当前 X-User-Id）；LLM 参数中 userId 一律服务端覆盖。
3. **Prompt 注入防护**：system prompt 中声明工具结果为"不可信数据"，工具返回内容中的指令样式文本不得改变数据边界；用户消息与工具结果分区块注入。
4. **配额与限流**：每日次数查 `agent_quota`（原子自增）；单用户并发 1 个进行中请求（分布式锁或 DB 乐观锁）；服务级 QPS 限流。
5. **成本控制**：LLM 网关记录每次调用的 token 用量（`agent_tool_log` 与 message 关联），每日成本看板 `[P1]`；上下文截断（3.2）是第一道成本闸门。
6. **内容合规**：用户输入与 LLM 输出过内容安全检查（智谱自带审核或平台审核接口 `[TBD]`），命中则返回统一兜底话术。
7. **敏感信息**：日志与 tool_trace 中不落完整题目解析正文（截断摘要），避免库内二次存储版权内容。

## 8. 可观测性

- **日志**：每次提问一条链路日志（session/message/round/tool/cost_ms/token），按 message_id 串联；
- **指标**：日均提问量、工具成功率、平均调度轮次、P95 响应时长、单次平均 token 成本；
- **告警**：工具失败率 > 20%（10 分钟窗口）触发告警；LLM 网关 429/超时率告警。

## 9. 与现有 AI 基建的边界

| 事项 | 批量出题（现有） | 学习助手（新） |
|---|---|---|
| 触发方 | 管理后台管理员 | 小程序登录用户 |
| 服务 | poti-question AI 任务机制 | poti-agent |
| 用途 | 内容生产（离线） | 实时对话调度 |
| 隔离要求 | 互不复用任务表与并发池，仅共享智谱账号与密钥配置方式 | — |

两个体系共用密钥但**独立限流与并发池**，避免出题高峰挤占助手响应。
