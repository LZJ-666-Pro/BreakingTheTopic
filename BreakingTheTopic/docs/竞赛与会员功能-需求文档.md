# 竞赛与会员功能需求文档（PRD）

> 版本 v1.0 · 2026-10-17 · 破题小程序 · 状态：已评审待开发

## 1. 背景

小程序当前具备刷题、错题本、面试特训、AI 导师等能力，但缺少运营活动载体（竞赛）与商业化路径（会员）。本迭代新增两大功能，为毕业设计完整度与运营演示提供支撑。

## 2. 竞赛功能

### 2.1 需求概述

管理员在后台创建限时答题竞赛并发布；用户在小程序浏览竞赛列表、报名、在时间窗内开赛限时答题，交卷后按「得分 + 用时」排名，可查看排行榜与个人成绩。

### 2.2 角色与功能清单

| 端 | 角色 | 功能 |
|---|---|---|
| 后台 | 管理员 | 竞赛 CRUD（草稿→发布→进行→结束）、设置题库分类/题目数/时长/时间窗、查看报名与成绩列表、删除（草稿/已结束） |
| 小程序 | 用户 | 竞赛列表（报名中/进行中/已结束）、详情、报名、开赛限时答题、交卷、成绩与排行榜 |

### 2.3 竞赛状态机

```
草稿(0) --发布--> 报名中(1) --到达开赛时间--> 进行中(2) --到达结束时间--> 已结束(3)
```
状态不落库硬编码，由 start_time / end_time 与 status 动态推导，避免定时任务依赖：
- status=0 草稿（后台手动保存）
- status=1 已发布：now < start_time
- 进行中：start_time ≤ now ≤ end_time
- 已结束：now > end_time
后台「发布」仅将 status 0→1（不可逆）；用户报名窗口 = 发布后且未到结束时间。

### 2.4 业务规则

- R1 同一竞赛每用户仅可报名一次（唯一索引 user_id+competition_id）
- R2 进行中每用户仅可作答一次；开赛后计时器倒计时（duration 分钟），到时自动交卷
- R3 试卷由后端从指定分类随机抽题（question 服务 Feign），每人题目一致（开赛时生成快照存 competition_record.question_ids，保证公平）
- R4 交卷即时判分：答对数×每题分值（总分=题目数×10），用时短者优先
- R5 已交卷后展示排行榜（前 50 名）与个人排名；未交卷用户看不到题
- R6 排行榜分数相同按用时升序；用时相同按交卷时间早者优先

### 2.5 数据模型（poti_practice 库）

- `competition`：id/title/description/category_id/question_count/duration_minutes/start_time/end_time/score_per_question/status/created_by/create_time/update_time/deleted
- `competition_signup`：id/competition_id/user_id/create_time（uk：competition_id+user_id）
- `competition_record`：id/competition_id/user_id/question_ids(json)/answers(json)/score/correct_count/cost_seconds/submit_time（uk：competition_id+user_id，未交卷即报名开赛记录）

### 2.6 接口清单（poti-practice 8400，经网关 /practice/**）

用户端：`GET /competition/page`（分页+动态状态）、`GET /competition/{id}`（详情+我的报名/成绩状态）、`POST /competition/{id}/signup`、`POST /competition/{id}/start`（返回题目列表-剥离答案）、`POST /competition/{id}/submit`（answers[{questionId,answer}]）
后台：`POST /admin/competition/page`、`POST /admin/competition/save`、`POST /admin/competition/publish/{id}`、`GET /admin/competition/{id}/records`、`DELETE /admin/competition/{id}`
依赖：poti-question 新增 `GET /question/internal/random?categoryId=&limit=`（随机抽题，Feign 带内部令牌）

## 3. 会员功能

### 3.1 需求概述

用户可开通月度 VIP 会员，享有差异化权益；管理员查看会员订单与会员用户。**支付已接入微信支付 V3 JSAPI**（官方 wechatpay-java SDK）：配置商户参数后走真实支付（wx.requestPayment 拉起收银台 + 回调/查单双重确认）；未配置或配置不全时**自动降级模拟支付**（点击支付即成功，订单标记 simulated=1），无需改代码即可切换。

### 3.2 会员权益（MVP 两个）

| 权益 | 说明 | 实现点 |
|---|---|---|
| AI 导师提问次数提升 | 普通用户每日 20 次 → VIP 每日 100 次 | poti-agent 每日限额校验时查询会员状态 |
| 专属 VIP 徽标 | 「我的」页昵称旁金色徽标 | user 表 vip_level 字段随用户信息下发 |

### 3.3 业务规则

- M1 价格读后台「系统配置-会员设置」三档价格（vip_price / vip_price_quarter / vip_price_year），保存后实时生效
- M2 开通/续费生成订单：模拟支付直接成功；真实支付订单先落库为待支付（pay_status=0），回调/查单确认后置 1 并开通会员，expire_time = max(now, 当前到期) + months*30 天（未过期续费顺延，数据库端原子计算）
- M3 到期后 vip_level 自动失效（查询时按 vip_expire_time 动态判断，不依赖定时任务）
- M4 支付渠道标记：simulated=1 模拟支付（transaction_id 前缀 MOCK），simulated=0 真实微信支付（记录微信 transaction_id）
- M5 支付结果确认双通道：微信回调 /vip/pay/notify（验签+AES-GCM 解密，幂等）为主；前端 wx.requestPayment 成功后轮询 /vip/pay/query（后端向微信主动查单对账）为补偿

### 3.3.1 微信支付配置（poti-user application-dev.yml，均可环境变量覆盖）

```yaml
wx:
  pay:
    enabled: ${WX_PAY_ENABLED:false}          # 总开关
    mch-id: ${WX_PAY_MCH_ID:}                 # 商户号
    mch-serial-no: ${WX_PAY_SERIAL_NO:}       # 商户API证书序列号
    api-v3-key: ${WX_PAY_APIV3_KEY:}          # APIv3密钥（32位）
    private-key-path: ${WX_PAY_PRIVATE_KEY_PATH:}  # apiclient_key.pem 绝对路径
    notify-url: ${WX_PAY_NOTIFY_URL:}         # 回调地址（公网 https）
```

启用真实支付步骤：商户平台申请微信支付 → 拿到商户号/APIv3密钥/下载 apiclient_key.pem → 设置五个环境变量（或改 yml）→ notify-url 填公网地址（本地开发用内网穿透如 natapp）→ 重启 poti-user。商户参数需与小程序 appid（wx.appid）完成关联绑定。

### 3.4 数据模型（poti_user 库）

- `user` 表加列：`vip_level`(tinyint 0/1)、`vip_expire_time`(datetime NULL)
- `vip_order`：id/user_id/order_no/amount/months/pay_status(1成功)/simulated/create_time/pay_time（模拟支付即时落单）

### 3.5 接口清单（poti-user 8200，经网关 /user/**——小程序直连 8200）

用户端：`GET /vip/status`（是否VIP/到期时间/价格）、`POST /vip/purchase`（months，模拟支付开通）
内部：`GET /vip/internal/status?userId=`（agent 与其他服务查询）
后台：`GET /admin/vip/order/page`、`GET /admin/vip/user/page`（会员用户列表）——由 poti-user 提供数据、poti-admin 不跨库，后台走 vite /user-api 代理直连（与现有反馈页直连模式一致的例外，或经网关 /user/**）

**决策**：后台会员页与竞赛页统一走统一 api（网关），避免再造直连例外。

## 4. 测试要点

- 竞赛：状态推导（发布前后/时间窗边界）、重复报名拦截、重复开赛拦截、倒计时自动交卷、判分正确性、排行榜并列排序、未报名开赛 403 类拦截、草稿不可见（用户端只出现已发布）
- 会员：重复购买顺延计算、到期后权益回收（AI 次数回落 20）、模拟支付订单落库、价格配置联动
- 权限：普通管理员看不到竞赛/会员菜单（permissions 过滤）；超管全量可见
- 兼容：竞赛/会员新接口不影响既有刷题/统计链路

## 5. 非功能约束

- 全部新接口遵守现有双层鉴权（网关 JWT + 服务过滤器），身份一律取 X-User-Id 不信任前端传参
- 分页接口返回 {list,total} 结构、前端默认分页条数接 sys_config（default_page_size）
- 竞赛答题接口剥离 answer 字段（防作弊，与搜题工具一致）
